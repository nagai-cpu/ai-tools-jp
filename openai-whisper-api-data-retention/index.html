経路ごとの保持と学習

2026年11月7日に、OpenAI APIドキュメントの「Data controls in the OpenAI platform」「Deprecations」「Transcription」「File transcription」「Realtime transcription」「Pricing」、各モデルのページ、「エンタープライズプライバシー」（2026年1月8日更新）、「サービス契約」（2026年1月1日発効）、ヘルプのデータ共有のページを読んで確認しました。

ZDRはZero Data Retention（ゼロデータ保持）の略です。ライブの行は当サイトの読みです。表に文字起こしセッションの個別の行はなく、ガイドの接続先が/v1/realtime?intent=transcriptionなので/v1/realtimeの行を当てました。

「最大30日」と「None」はどちらが正しいか

同じページの本文は、不正利用監視のログは既定で全機能に生成され、最大30日保持すると書いています。一方で表の音声文字起こしの行は「None」です。

手がかりはエンタープライズプライバシーです。最大30日の説明は「一部のエンドポイントおよび機能を除き」と始まり、例外はドキュメントに記載とされています。そこで個別の表を優先して読みました。

ただし「None」の定義は書かれておらず、音声を消す時点も確認できませんでした。「送った瞬間に消える」と社内に説明するのは言い過ぎです。

判断軸1｜録音ファイルか、ライブ音声か

公式のガイドは、完了した録音はファイルの文字起こし、マイクや通話の音声はRealtimeと分けています。保持の行もここで分かれます。

gpt-transcribeはファイルとRealtimeの両方に対応するので、Realtimeで使えば経路が変わります。社内の説明にはモデル名だけでなく経路を書きます。

30日の行を避けつつ即時性も要るなら、ZDRかModified Abuse Monitoringの申請が候補です。どちらも現時点ではOpenAIの事前承認と追加要件の受諾が条件で、窓口は営業です。承認後でも、顧客によってモデルを対象外にする権利をOpenAIは留保しており、その場合は事前に書面で通知するとされています。

判断軸2｜2027年2月26日の移行で何が変わるか

Deprecationsによると、通知は2026年8月26日です。whisper-1とgpt-4o系の文字起こし3種が対象で、推奨の移行先はgpt-live-transcribeかgpt-transcribeです。/v1/audio/translationsも同日に終わり、移行先はv1/realtime/translationsです。

  • ファイルのまま移るなら：gpt-transcribeは同じ経路なので、表の行は変わりません
  • ライブに切り替えるなら：gpt-live-transcribeの対応先はRealtimeの文字起こしだけです。30日の行に入ると読めるので、保持の説明を書き直します
  • 翻訳を使っているなら：移行先は表に個別の行がなく、保持は確認できませんでした。ファイルのアップロードとも別の形です
  • 話者ラベルや字幕を使っているなら：公式の案内はgpt-4o-transcribe-diarizeとwhisper-1の例で、どちらも削除の対象です

公式は、モデルIDを替えるだけでは全機能は維持されないと書き、代表的な音声で試すよう勧めています。ファイルの上限は25MBで、超える録音は圧縮か分割です。

判断軸3｜保持の外に何が残るか

データ共有の設定：入出力の共有は既定オフで、組織のオーナーがオンにできます。一部の組織には無料トークンの特典があるので、特典目当てでオンにしたプロジェクトがないか確認します。音声の文字起こしが共有の対象に入るかは確認できませんでした。

日本リージョン：表の日本は保存がYes、処理がNoで、音声の処理リージョンは米国と欧州です。処理に対応しないリージョンでは、リージョン外で処理と一時保存が行われる場合があると書かれています。利用には監視制御の承認とModified Retention amendmentの締結も要ります。国内処理を求める目的には合わないと読めます。保存先の考え方はAI文字起こしの保存先の比較にあります。

契約と録音相手：サービス契約の第4.2条は、明示の同意なしに顧客コンテンツを開発や改善に使わないと定めます。第4.3条は、入力に必要な権利や許可を持つことを利用者の責任としています。

自社側の保存：自社のログやストレージに残る音声と結果は別です。APIを組み込んだ他社のアプリなら、その規約も読みます。期間の決め方は文字起こしデータの保存期間と削除設定に書きました。

音声を社外に送らない要件ならWhisperをローカルで動かす方法が比較に入ります。ChatGPTの画面で録音する場合はChatGPT Team・Enterpriseの音声の扱いを見てください。

開発しないならNottaは候補か

APIは音声を文字にする部品です。録音、権限、保存先は自社で組みます。開発の手を割けない場合の候補がNottaです。

ヘルプによると、ビジネス Plus（年64,800円・税抜）とエンタープライズは音声認識の「AI学習なし」で、音声と認識結果はパートナー側に保存されず、メモリ上で処理されます。ビジネスプランは比較表で音声認識のAI学習が「あり」です。

ただし、Notta本体の録音データはAWS東京リージョンに保存され、手動で消すまで残ります。保持の短さを最優先するなら、Nottaは合いません。 向くのは、開発なしで会議の記録を共有し、学習なしを契約プランの条件として持ちたい法人です。

よくある質問

Whisper APIに送った音声は学習に使われますか

公式の表で/v1/audio/transcriptionsの学習は「No」です。2023年3月1日以降、APIのデータは明示のオプトインがない限り学習に使わないと書かれています。組織のデータ共有の設定は確認してください。

「APIは最大30日保持」という説明と違いませんか

その説明は一般論で、エンタープライズプライバシーは一部のエンドポイントを除くと書いています。ファイルの文字起こしの行は「None」、Realtimeは「30 days」です。

ローカルのWhisperも2027年に終わりますか

読んだ通知はAPIからの削除についてのものです。自分のPCで動かすオープンソース版への言及は、Deprecationsには見当たりませんでした。

まとめ

  • ファイルの/v1/audio/transcriptionsは学習「No」、保持は「None」。Realtimeは「30 days」で、保持は経路で分かれる
  • whisper-1は2027年2月26日に削除予定。gpt-transcribeなら同じ経路だが、話者ラベルや字幕は別途検証が要る
  • データ共有の設定、日本リージョンの処理、自社の保存は別に確認する。開発しないならNottaのビジネス Plus以上も候補だが、データは消すまで残る
