Amazon Transcribeの学習オプトアウト｜AWSの設定と残る確認

2026-11-06 公開

この記事にはアフィリエイト広告（PR）を含みます。無料プランで実際に試した範囲の内容で、報酬額で順位を変えることはしていません。

結論から言うと、Amazon Transcribeは未設定だと、AWS Service Terms第50.3条により音声が改善目的で利用・保存される場合があります。止める場所はTranscribeの画面ではなく、AWS OrganizationsのAIサービスのオプトアウトポリシーです。設定できるのは管理アカウントで、S3の音声や結果の管理は別に残ります。

オプトアウトで変わること、変わらないこと

2026年11月6日に、AWS Service Terms（11月5日更新）第50条、Organizationsのユーザーガイド、Transcribeの開発者ガイドとFAQを確認しました。

論点未設定のときオプトアウト後残る確認
改善への利用第50.3条(a)：当該サービスと基盤技術の開発・改善に利用・保存できる利用・保存しないよう指示した状態有効ポリシーの記録
AWSと関連会社のAI技術第50.3条(b)：個人データでないものに限り利用できる同上組織内の子ポリシーの上書き
別リージョンへの保存第50.3条(c)：改善に関してのみ、利用リージョン外に保存する場合があるFAQは別リージョンに保存されないと説明通常処理の保存先リージョン
改善用に保存済みの写し残る場合があるサービスが削除。提供に必要なものは対象外サポートへの削除依頼の要否
文字起こし結果自社のS3か、既定バケット変わらない既定バケットは90日のジョブ期限で削除
入力の音声自社のS3変わらない自社で削除とアクセス管理

オプトアウトは改善目的の利用を止める設定で、音声の送信を止めるものではありません。送信の有無が論点ならクラウド文字起こしとオンプレの比較を見てください。

判断軸1｜全サービスを止めるか、Transcribeだけか

ポリシーには、全サービスを表すdefaultと、個別のtranscribeがあります。defaultは将来追加されるAIサービスも含むと説明されています。

結果をComprehendやTranslateに渡す構成なら、どちらも第50.3条の列挙にあるのでtranscribeだけでは足りません。分ける理由がなければ全サービスのほうが漏れを防げます。

Transcribeだけを止める形は次のとおりです。公式の例のrekognitionをキー名transcribeに置き換えました。

``json { "services": { "transcribe": { "opt_out_policy": { "@@assign": "optOut", "@@operators_allowed_for_child_policies": ["@@none"] } } } } ``

@@noneが無いと、子ポリシーでoptInへ上書きできます。大文字小文字が違うとポリシーは機能しないとも書かれています。

判断軸2｜管理アカウントに手が届くか

公式の手順は、組織の管理アカウントでサインインする前提です。流れは、ポリシー種別の有効化、作成、ルート・OU・アカウントへの添付、有効ポリシーの確認です。全サービスのポリシーについて、公式は「Member accounts cannot update the policy.」と書いています。

  • 単独のAWSアカウント：Service Termsが示す方法はOrganizationsのポリシーです。組織を作ると、そのアカウントが管理アカウントになります。Organizationsは追加料金なしと案内されています
  • 組織のメンバー：開発チームだけでは設定できません。管理アカウントの担当者への依頼が要ります
  • 請求代行などの契約：管理アカウントを自社が持たない場合は、誰が設定できるかを契約先に確認します（当サイトの注意書き）

設定後はaws organizations describe-effective-policy --policy-type AISERVICES_OPT_OUT_POLICY --target-id <アカウントID>で有効ポリシーを確認できます。社内説明にはこの出力を残します。反映までの時間は確認できませんでした。

注意点が1つあります。TranscribeのFAQには、Organizationsのポリシーで止める回答と、AWS Supportへの連絡でオプトアウトした場合という回答が併存しています。Service Termsはポリシーの方法を示しているので、この記事はそちらに沿いました。なお、Transcribeのデータ保護ページには改善利用やオプトアウトの説明が見当たりませんでした。

判断軸3｜オプトアウトの外に何が残るか

学習を止めても、次は利用者側の設定です。データ保護ページは責任共有モデルを前提に書かれています。

  • 結果の置き場：OutputBucketNameを指定しないと、結果は既定のバケットに置かれ、一時URIは15分有効です。自社バケットなら、削除するまで残ります
  • 暗号化：指定がなければ出力はSSE-S3です。KMSキーはOutputEncryptionKMSKeyIdで指定できます。通信はTLS 1.2です
  • 名前とタグ：課金や診断のログに使われることがあるので、機密情報を入れないよう公式が強く勧めています。顧客名をジョブ名に入れる運用は避けます
  • 日本語の個人情報：言語別の表で、日本語のRedaction（個人情報の伏せ字）の欄は「no」です
  • 録音される相手への説明：第50.4条は、エンドユーザーへの通知と必要な同意を利用者の責任としています

保存期間の決め方は文字起こしデータの保存期間と削除設定が参考になります。

東京リージョンの料金は、AWSのPrice List API（9月11日版）でバッチが毎秒0.0001ドル、ストリーミングが毎秒0.0001667ドルでした。TranscribeはS3やストリームの音声をテキストにするサービスなので、録音から共有までの画面や権限は自社で組むことになると読めます。ここが分かれ目です。

Nottaの「AI学習なし」は、ビジネス Plus（年64,800円・税抜）、エンタープライズ、士業向け特別プランの機能です。ヘルプによると、学習なしでは音声と認識結果が音声認識のパートナー側に保存されません。なお、NottaのデータがAWSの東京に保管されることと、この記事の設定は別の話です。

開発の手を割けず、学習なしを契約プランの条件として持ちたい法人には、上位プランの確認が近道になります。

よくある質問

オプトアウトすると過去の音声も消えますか

公式は、改善用に保存された過去のコンテンツをサービスが削除すると説明しています。提供に必要なものは対象外です。自社のS3の音声はこの説明の外で、自社で消します。

AWSアカウントが1つだけでも設定できますか

組織を作り、そのアカウントを管理アカウントとしてポリシーを付ける流れです。単独のままの別の方法は、読んだページには見当たりませんでした。

Transcribe Medicalも設定が要りますか

第50.3条はTranscribe Medicalに適用しないと定め、FAQも提供と維持以外に使わないと説明しています。ただしFAQの対応言語は米国英語です。

まとめ

  • 未設定だと第50.3条で改善目的の利用と別リージョン保存がありうる。止めるのはOrganizationsのポリシー
  • 全サービスのdefaultか個別のtranscribeを選び、管理アカウントで付け、有効ポリシーの出力を残す
  • S3の音声、結果の保存、暗号化、名前の欄、相手への説明は残る。言語別の表で日本語の伏せ字は「no」
