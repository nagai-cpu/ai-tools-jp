Azure Speechの音声データは保存・学習される？標準は残らず例外は3つ

2026-11-07 公開

この記事にはアフィリエイト広告（PR）を含みます。無料プランで実際に試した範囲の内容で、報酬額で順位を変えることはしていません。

結論から言うと、Azure Speechは公式文書で「顧客データをSpeechモデルの改善に使わない」と明記され、リアルタイムと高速文字起こしの音声は保存されません。残るのは音声ログ、バッチの結果、カスタム音声の3つです。社内説明では「学習されない」より、自社の構成でこの3つが動くかを確認します。

どの使い方で何が残るか

2026年11月7日に、Microsoft Learnの「Data, privacy, and security for Speech to text」「Speech service encryption of data at rest」、ログとバッチの手順ページ、Data Protection Addendum（DPA、2026年11月版）を読んで確認した内容です。製品名は現在、Azure Speech in Foundry Toolsです。

使い方音声文字起こし結果保存先と期間消し方・確認点
リアルタイム（ログ無効）サーバーのメモリ上で処理し保存しない保存しないなしログが無効のままか
高速文字起こし保持・保存しない保持・保存しないなし結果の受け取りは自社側
音声ログを有効化保存保存Speechの内部ストレージに30日手動削除はREST APIのみ
バッチ自社が指定した場所自社の保存先、指定なしならMicrosoft管理のコンテナtimeToLiveHoursで6時間〜31日削除APIか期限切れで消える
カスタム音声アップロードした学習・テスト用データを保存同左既定はMicrosoftのストレージ自社で削除、または自社ストレージ
コンテナ自社環境で処理し、クラウドのSpeechへ送らない同左自社環境課金の計量情報は送る

ログは既定で無効です。暗号化のページには、ログが無効でカスタマイズも使わなければ顧客データは保存されない、とあります。

判断軸1｜「学習されない」の根拠をどこに置くか

根拠の文言は暗号化のページにあります。

Microsoft does not use customer data to improve its Speech models.

一方、Speech to textのプライバシーのページには学習に触れた節が見当たりませんでした。DPAは顧客データをプロファイリング、広告、新機能のための市場調査に使わないと定めますが、Speechの学習を名指しした条文は見つかりませんでした。契約上の根拠まで要るなら、Microsoftの窓口に確認します。

同じ「Azureの音声」でも、次は別の文書です。

  • Azure OpenAI経由のWhisperなど：Foundry Modelsの文書の範囲です。学習には使わないとする一方、不正利用の監視で人が確認する場合の説明があります。音声入力への適用は明記を確認できませんでした
  • Voice Live：本体は保存しないとされますが、処理がリソースの地域外で行われる場合があります
  • Windowsの音声入力：Azure Speechを使いますが、設定の話は別です。Windowsの音声認識はデータを送信する？で整理しました

判断軸2｜保存が起きる設定を実装で止められるか

誤解しやすい点は次の4つです。

  • ログの優先順位：カスタムモデルのエンドポイントでログが有効だと、セッション側の設定は無視されます。コードでfalseにしても止まりません。既存エンドポイントのログを切るのはREST APIで、Speech Studioではできません
  • ログの削除：音声と文字は別のIDで、ID指定なら両方に要求を出します。削除は非同期で、1日以上かかる場合があります
  • バッチの保存先：destinationContainerUrlはpropertiesの中に書きます。ルートに書くと無視され、結果はエラーなしでMicrosoft管理のコンテナへ書かれると公式が警告しています
  • 一時URL：BYOS（自社のストレージをSpeechに紐づける仕組み）でsasValidityInSecondsを省くと、URLに5日有効の署名が付きます。最も安全な形として公式が示す値は0です

destinationContainerUrlの保存先は全外部通信の許可が条件です。閉じたストレージに置くなら、公式の案内はBYOSです。

文書の不一致も1つあります。ログの手順ページとFAQは保持を30日、BYOSのページは「Logging data is kept for 5 days」と書いています。どちらが正しいかは確認できませんでした。ログを使うなら自社環境で残り方を確かめます。保存期間の決め方は文字起こしデータの保存期間と削除設定が参考になります。

判断軸3｜場所と閉じ方の要件はどこまでか

地域ページには、リソースを作った地域で音声データを保存・処理するとあり、例外はVoice Liveです。東日本と西日本はリアルタイム、高速、バッチの対象ですが、LLM speechの地域一覧に日本はありません。

  • BYOS：処理後に顧客の成果物をSpeech側に残さないとされます。内容に由来しないメタデータは残ります。Customer Lockboxは非対応で、公式はBYOSを近い管理の手段としています
  • コンテナ：接続型は計量情報の通信が要り、既定ではAPIに認証がありません。切断型は審査があり、対象は戦略的な顧客やパートナーとされ、年単位の契約で購入時に全額がかかります
  • プレビュー機能：DPAは、個人データや規制対象のデータを原則としてプレビューで扱わないよう書いています

通信の有無が論点ならクラウド文字起こしとオンプレの比較も材料になります。

費用はAzure Retail Prices APIの東日本で、1時間あたりリアルタイム1ドル、高速0.36ドル、バッチ0.18ドルでした。無料枠は月5時間です。ただしAzure Speechは部品なので、録音画面、権限、共有は自社で作ることになります。ここが分かれ目です。

開発の手を割けず、録音から共有までをすぐ使いたい法人で、学習なしをプランの条件にしたいなら上位プランが候補です。自社の鍵、閉域の保存先、地域の指定が要件ならAzure Speechのほうが合います。

正直な短所

  • Azure Speech：画面のないAPIで、開発と運用の担当者が要ります
  • Azure Speech（ログ）：高負荷時に音声の一部が記録されない場合があり、正確な記録として頼らないよう公式が警告しています
  • Azure Speech（同意）：話者分離は声の特徴を一時的に使います。必要な同意や許諾は利用者の責任と公式が書いています。個別の判断は専門家へ
  • Notta（下位プラン）：利用規約は、プランに応じてパートナー企業が音声を学習に使う場合があるとしています。無料プランは機密用途に向きません
  • Notta ビジネス Plus：料金ページでSAML SSOと操作ログはエンタープライズの項目です。ノート自体はNottaに保存されます
  • この記事の限界：実機では試していません。公式文書の読み取りです

よくある質問

無料枠（F0）でも学習に使われませんか

公式の文言は無料と有料を分けていませんが、無料枠だけを取り上げた説明は確認できませんでした。料金ページによると、無料枠でバッチは使えません。

解約するとデータはいつ消えますか

DPAによると、無料試用などを除き、契約終了後90日は取り出し用に保持され、その後90日以内に削除されます。

BYOSにすれば音声はMicrosoftを通りませんか

通ります。BYOSは保存先を変える仕組みで、処理はSpeechが行います。送信そのものを避けるなら、コンテナかWhisperのローカル実行が比較対象です。

まとめ

  • 公式はSpeechモデルの改善に顧客データを使わないと明記。リアルタイムと高速は保存されず、ログも既定で無効
  • 残るのは音声ログ、バッチの結果、カスタム音声。ログの優先順位と保存先の書き方で、意図せず残る場合がある
  • ログの保持は30日と5日で文書が不一致。開発の手がなく学習なしを条件にしたい法人はNottaの上位プランも比較する
